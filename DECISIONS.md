# Решения по проекту «Подорожники+»

Работа шла в режиме нон-стоп, спорные места решены самостоятельно. Здесь — что выбрано и почему.

## Источники и окружение

1. **Образец движка.** `./reference-engine` распакован из `res/new-wolf-site.zip` (Node-движок FOX/WOLF). Взяты идеи, не код: разделение `src/core` (движок: БД, i18n, шаблоны, картинки, безопасность, статистика, почта, LLM) и `src/project` (контент сайта), контроллеры с `register(app)`, Nunjucks, переводы в `languages/*.json`, JSON-LD из данных, MCP по схеме `mcp/index.js + protocol.js + tools/*`, своя статистика визитов. Хранение — PostgreSQL вместо JSON-файлов, поэтому у MCP нет `pm2 restart` после записи.
2. **Сеть.** Встроенный Chromium Playwright на этой машине получает `ERR_NETWORK_ACCESS_DENIED`, поэтому краулер и visual diff запускаются с `PW_CHANNEL=chrome` (системный Chrome). В Docker и на чистой машине переменная не нужна.
3. **Подсеть Docker.** Пулы адресов Docker на машине исчерпаны другими проектами; в `docker-compose.yml` задана явная подсеть `10.77.31.0/24` (переопределяется `COMPOSE_SUBNET`). Чужие сети не трогались.
4. **Порты.** Приложение `8350`, Postgres наружу только на `127.0.0.1:5440` (5432/3306 и соседние заняты).
5. **Репозиторий.** По указанию пользователя код выкладывается в существующий `https://github.com/realmag777/travel-stories`, а не в новый `podorozhnyky-plus` (`gh` на машине не установлен; пуш через git). Репозиторий публичный — владелец решил оставить его таким (30.10.2026).

## API

6. **Контракт v1 = оригинал целиком.** По уточнению пользователя повторены все 20 операций Swagger оригинала, включая `auth/*`, `users/me`, `stories/own|saved`, создание/правку историй (multipart), избранное. Тот же конверт `{status, message, data}`, те же сообщения («Successfully found stories!» и т.д.), лимиты (`perPage ≤ 20`, `limit ≤ 50`, popular `≤ 12`), формат ошибок валидации celebrate/Joi (`statusCode/error/message/validation`), cookie-сессии `accessToken/refreshToken/sessionId`. OpenAPI оригинала взят как основа `/docs`, к нему добавлены пути v2.
7. **Регистрация в UI отключена, в API — есть.** Задание просит «регистрации нет», уточнение — «REST API должно быть таким же». Компромисс: эндпоинты `auth/register|login` работают (API-совместимость), а «Вхід/Реєстрація» на сайте выглядят как в оригинале, но ведут на страницу о публикации через редакцию.
8. **Расширения только под `/api/v2`**: фасеты, поиск, карта, анонимные сохранения, бронирование, ссылки «Де зупинитися».
9. **24-hex id.** Импортированные записи сохраняют свои `_id`; новые генерируются как ObjectId (время + случайная часть). Демо-записи — детерминированные id с временем публикации внутри, чтобы повторный bootstrap давал те же id.

## Данные

10. **Импорт оригинала — снапшот в репозитории + живое обновление.** `tools/import-original.js` (только GET) пишет `seeds/original/*.json` и картинки (перекодированы в JPEG ≤1280 px, 26 МБ вместо 52). При первом старте контейнера снапшот обновляется из живого API, если он доступен; иначе берётся закоммиченный. Так `docker compose up -d` работает и без интернета.
11. **Модерация импортированного.** В оригинале много тестовых записей («ТТТТ…», «ND_TEST_CREATE», 17 копий одной QA-истории). Ничего не удаляется: такие истории получают `hidden = true` (правило в `tools/load-seed.js → moderateOriginal`), из публичных списков, счётчиков, API и sitemap они исчезают, в админке их можно вернуть. Видимыми остались 104 из 168 историй оригинала. Пользователи без видимых историй и без описания, а также с e-mail вместо имени тоже скрыты.
12. **Демо-контент** (80 мандрівників, 250 историй, uk + en) написан пятью параллельными агентами по общему брифу `seeds/BRIEF.md` и проверен `tools/validate-seed.js` (длины 800–2500, словари фасетов, координаты, уникальность). Регионы мира поделены между агентами, чтобы места не повторялись.
13. **Фото** — Wikimedia Commons API без ключа, только свободные лицензии (CC BY / BY-SA / CC0 / PD), горизонтальные ≥1200 px. Автор, лицензия, ссылки сохранены в БД и выводятся под обложкой. Аватары — `randomuser.me/api/portraits`. Медиа закоммичены (`seeds/media`, 49 МБ), чтобы чистый старт не зависел от сторонних сервисов.
14. **Даты и популярность** демо распределены по последним 12 месяцам детерминированно (хэш ключа), favoriteCount с «длинным хвостом» (8% историй 40–85 сохранений, остальные 0–37).
15. **Бронирование в демо:** каждый 5-й демо-мандрівник — гид с двумя услугами и слотами на 6 недель вперёд (16 гидов, ~1500 слотов) и тремя демо-бронями, чтобы админке было что подтверждать.

## Фильтр и поиск

16. **ЧПУ фильтра:** `/stories/filter/country-it,jp/season-spring/budget-low/trip-family/days-4-7/tags-food`, категория и сортировка — query (`?category=` совместим с оригиналом). Сегменты и значения сортируются — URL канонический, неканонический редиректится 301. Тот же модуль `src/shared/filter-state.js` используется сервером и браузером.
17. **Семантика:** внутри фасета — ИЛИ, между фасетами — И. Счётчики считаются «дизъюнктивно»: для каждого фасета — с учётом всех остальных активных фильтров, одним SQL-запросом (`UNION ALL`), массивы через GIN-индексы. Варианты с нулём — неактивны, выбранные показываются всегда.
18. **Мгновенное обновление** без SPA: каждая опция — настоящая ссылка на SSR-страницу; JS перехватывает клик, запрашивает тот же URL с заголовком `X-Partial` и подменяет фрагменты (результаты, фасеты, чипы, категории), меняя адрес через `history.pushState`. Без JS всё работает обычными переходами.
19. **Длительность** — бакеты 1–3 / 4–7 / 8–14 / 15+ дней (точное число дней хранится, фасет по бакетам). Сезон и теги — массивы. Регион — slug из английского названия.
20. **Поиск обычным языком:** при наличии LLM — запрос к модели со строгой JSON-схемой и списками допустимых значений, ответ проверяется zod; при любой ошибке или без ключа — встроенный разборщик на правилах (месяцы→сезоны, бюджет, тип поездки, длительность, теги, категории, страны и регионы из БД с учётом украинских падежей). `LLM_PROVIDER = anthropic | openai-compatible`, модель по умолчанию `claude-haiku-5-5`. Без JS форма поиска ведёт на `/stories/search`, который редиректит на ЧПУ.
21. **Карта:** Leaflet + markercluster из npm (локально), тайлы OSM. «Шукати у видимій області» добавляет `bbox` в состояние фильтра — счётчики фасетов пересчитываются по области, а маркеры показываются по остальным фасетам (чтобы при панорамировании точки не пропадали).

## Вёрстка

22. **Пиксельное совпадение** проверяется `tools/visual-diff.js` на живом оригинале: с обеих сторон картинки делаются невидимыми, текст прозрачным (контент разный), у нас скрываются блоки новых функций (`data-extra`). Итог — 0.00% на всех страницах, кроме auth (там вместо формы — плашка редакции).
23. **modern-normalize** подключён по ТЗ, но он задаёт `line-height: 1.15`, а у оригинала `normal` — возвращено `normal`, иначе карточки «плыли» на 2–20 px.
24. **Число карточек как у оригинала:** /travellers — 8 ниже 1440 px и 12 на десктопе, профиль — 4 и 6. Сервер отдаёт десктопный набор, на узких экранах JS обрезает и переключает «Показати ще» на `offset/limit` (CSS скрывает лишние до выполнения скрипта).
25. **Новые блоки** в той же системе: панель фильтра и чипы — в стиле категорий оригинала, «Список / Карта» — его сегментированные табы, модалка подтверждения в админке — его модалка, ошибки полей — его `errorMessage`, лоадер — его спиннер + полоска.
26. **Иконка YouTube.** В спрайте оригинала нет `icon-youtube` (там пустое место); добавлена — это видимое различие в футере, сознательно.
27. **Шрифты** локально из `@fontsource` (Nunito Sans 400–700, Inter 700, Sora) с теми же metric-override fallback, что генерировал next/font у оригинала.

## Безопасность и прочее

28. **Сессии только для /admin** — публичные страницы без cookie. Анонимное сохранение: id в localStorage, на сервер уходит только изменение счётчика; одна «голосовалка» на visitor-hash (IP+UA+секрет) и историю, плюс rate limit по IP и по IP+storyId, плюс проверка Origin.
29. **CSRF** — токен в сессии, для multipart передаётся в query. Логин — bcrypt, `session.regenerate`, rate limit 10/15 мин.
30. **Статистика без внешних сервисов:** буфер в памяти → `page_views` пачками раз в 10 с; боты и автотесты (`HeadlessChrome`, `x-no-track`) не считаются, поэтому на свежей установке графики честно пустые.
31. **Письма** без SMTP пишутся в лог контейнера; ошибка SMTP никогда не ломает бронирование.
32. **Двойное бронирование** исключено дважды: `SELECT … FOR UPDATE` слота в транзакции и частичный уникальный индекс `bookings(slot_id) WHERE status <> 'cancelled'` (проверено тестом с 8 параллельными попытками).
33. **Переводы контента:** uk и en из сидов; es и новые истории — кнопка «Перекласти» (LLM). Без перевода показывается украинский текст с пометкой и `lang="uk"`.
34. **Демо-очистка** удаляет `is_demo` истории и демо-мандрівников без реальных историй, их файлы, а затем осиротевшие страны; флаг в `settings.bootstrap` не даёт bootstrap пересоздать демо после рестарта.
35. **Нагрузочный тест** идёт в отдельной БД `<db>_load` (создаётся и удаляется скриптом), чтобы не засорять сайт 10 000 синтетических историй.

## Гиды (раздел «Гіди»)

36. **Кто гид.** Мандрівник с флагом «приймає бронювання» и хотя бы одной активной услугой. В демо это 25 сгенерированных мандрівників, отобранных детерминированно по хэшу ключа; импортированные из оригинала гидами не становятся. Услуги берутся из каталога: консультация 30 и 60 минут, пешеходная экскурсия, планирование маршрута, по 1–3 на гида. Цена для показа — в евро, слоты — на 30 дней по пяти разным недельным расписаниям.
37. **Страна и регион гида** вычисляются из его историй: самая частая страна, регион — из последней истории в этой стране (иначе выходило «регион из Лаоса, страна Индонезия»).
38. **Цена «від …»** — минимальное число из `price_label` активных услуг. Цены хранятся строкой для показа, оплаты нет.
39. **Подтверждение брони** — `/booking/<public_token>`: 128-битный токен, `noindex`, `no-store`. Отмена идёт по отдельному `cancel_token`. Он одноразовый: стирается тем же UPDATE, который отменяет бронь, и при отмене из админки тоже. Подтверждение бронь из админки выдаёт новый ключ отмены. Отмена — это POST с проверкой Origin, GET показывает только экран подтверждения.
40. **Новые элементы в шапке, на главной и в профиле** помечены `data-extra`, поэтому visual diff с оригиналом по-прежнему 0.00%.

## Демо одной командой

41. **Снимок, а не сид.** Демо поднимается из `demo/db/demo.dump` (`pg_dump -Fc`, 0,6 МБ) и `demo/uploads`. При первом старте Postgres восстанавливает дамп через `docker-entrypoint-initdb.d` — это срабатывает только на пустом каталоге данных, поэтому повторный старт ничего не перетирает. Приложение в `DEMO_MODE=1` выполняет только миграции (на свежем снимке их нет) и один раз копирует картинки в свой том. Импорт с оригинала, Wikimedia, randomuser и генерация не вызываются.
42. **Снимок снимается без изменения рабочей БД.** `tools/demo-snapshot.js` делает дамп в отдельную временную базу и чистит её. Удаляются сессии админки, cookie-сессии API, хэши анонимных голосов и учётки, созданные тестами контракта. Все брони обезличиваются: «Гість N» / `guestN@example.com`, текст сообщения заменён. Секреты LLM/SMTP и партнёрские ID обнуляются. Статистика (`page_views`, `search_events`) остаётся: это состояние админки, а не служебный лог. Счётчиков rate limit в БД нет, они живут в памяти процесса.
43. **Пароль админа хранится не в базе.** Логин админа задаётся переменными `ADMIN_USER` и `ADMIN_PASS_HASH`, поэтому демо-пароль `demo-admin-2026` и его bcrypt-хэш лежат в `.env.demo`. В дампе админских паролей нет. Сохранённая статистика ссылается только на хэши посетителей.
44. **Картинки лежат в git, без Release.** Uploads занимают 158,5 МБ (2334 файла, крупнейший 403 КБ), то есть меньше порога 200 МБ, а каждый файл меньше 50 МБ. Пережатие и архив в GitHub Release не понадобились, скрипт демо ничего не скачивает. Картинки копируются в именованный том, а не монтируются напрямую, чтобы загрузки в админке не меняли папку репозитория и `demo-reset` возвращал ровно снимок.
45. **Ассеты в репозитории.** Шрифты лежат в `public/fonts`, modern-normalize и Leaflet с markercluster — в `public/vendor` вместе с лицензиями. Сборка берёт их оттуда: esbuild-alias для Leaflet, CSS — напрямую. CDN нет. Из сети при сборке образа загружаются только базовые Docker-образы и npm-зависимости сервера. На карте тайлы OpenStreetMap, это единственное, что требует интернета в работе.
46. **Порт и сеть.** Порт по умолчанию 8080 меняется одной переменной `APP_PORT`, и `PUBLIC_URL` подстраивается сам (`http://localhost:${APP_PORT}`). Сайт слушает только `127.0.0.1`. У демо своё имя compose-проекта (`podorozhnyky-demo`), свои тома и подсеть `10.77.32.0/24` (`DEMO_SUBNET`), так что оно не пересекается с рабочим стеком.
47. **`npm run demo`** вызывает `scripts/demo.js`, а тот — `demo.ps1` на Windows и `demo.sh` в остальных системах. Сами скрипты Node.js не требуют. В `.ps1` стоит UTF-8 BOM, чтобы Windows PowerShell 5.1 правильно показывал кириллицу.
48. **Короткие пути.** Проверка с чистого клона на Windows упала: имена ассетов краулера были до 133 символов, и в глубокой папке путь превышал 260 символов. Теперь ассеты называются `<sha1-12>.<ext>`, а исходный URL хранится в `index.json`. Самый длинный путь в репозитории — 69 символов.
